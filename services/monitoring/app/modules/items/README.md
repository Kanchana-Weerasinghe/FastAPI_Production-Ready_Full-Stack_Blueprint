# items module

Generated by `python scripts/new_module.py monitoring items`: a **small example that shows every
concept of the architecture once**, in the file where it belongs. Read this page, follow one request through
the files, then replace the example with your real rules (keep the same files and layers).

## The example

Each **Item** has an `id`, a `name`, a `code` and a `status`.

| Field | Rule | Example |
| :--- | :--- | :--- |
| `name` | 3-120 characters, extra spaces removed | `"Blue pen"` |
| `code` | 2-20 letters, digits or `-`, upper case, **unique** | `"itm-001"` → `"ITM-001"` |
| `status` | `active` → `archived` → `active` | new items are `active` |

Business rules (all in `domain/policies.py`):

1. The code must be unique.
2. An archived item cannot be renamed or get a new code (restore it first).
3. A item cannot be archived twice; only an archived one can be restored.
4. Only an archived item can be deleted (archive it first).

## Where does my code go?

| I am writing... | It goes in | In this example |
| :--- | :--- | :--- |
| A **format check** on one value ("2-20 characters") | `domain/value_objects.py` | `ItemName`, `ItemCode` |
| A **check**: "is this allowed?" | `domain/policies.py` (**every** business rule) | `ensure_code_is_free`, `ensure_is_active`, `ensure_can_archive`, `ensure_can_delete` |
| A **change**: set fields, record an event | An **entity method**, which calls its policy first | `create`, `rename`, `change_code`, `archive`, `restore`, `delete` |
| A **step**: load, fetch a fact, save, publish | The **use case** | `ItemUseCases.create`, `.update`, `.archive`, ... |

Every entity method has the same 3 lines: **1. rule** (policy) → **2. change** → **3. event**. Use cases
never set fields directly, so a rule can never be skipped.

A rule that needs other records ("the code must be unique") works the same way: the use case fetches the
fact (`repository.code_exists(...)`) and passes it to the entity method (`code_taken=...`), which gives it
to the policy.

## All the concepts

| Concept | File | Holds |
| :--- | :--- | :--- |
| **Value object** | `domain/value_objects.py` | Self-checking values |
| **Policy** | `domain/policies.py` | All business rules (checks only, no changes, no database) |
| **Entity** | `domain/entities.py` | The data + the methods that change it (rule → change → event) |
| **Domain error** | `domain/exceptions.py` | One class per broken rule, with a status and a stable `code` |
| **Domain event** | `domain/events.py` | Facts that happened (`ItemCreated`, `ItemArchived`), published after commit |
| **Port** | `application/ports/` | Interfaces the use cases need (`ItemRepository`, `EventPublisher`) |
| **Use case** | `application/use_cases/` | The steps of one action: load → fetch facts → call one entity method → save → publish |
| **Adapter** | `infrastructure/` | Port implementations (`SqlAlchemyItemRepository`, `LoggingEventPublisher`) |
| **Schema** | `schemas.py` | JSON shapes in and out (HTTP only) |
| **Router** | `router.py` | Endpoints: access check, rate limit, one use-case call; never checks roles |
| **Container** | `container.py` | Which adapter implements each port |
| **Public API** | `public.py` | What other modules may import |

## Endpoints

| Method | Path | operationId | Success | Errors |
| :--- | :--- | :--- | :--- | :--- |
| POST | `/v1/items/` | `createItem` | 201 + `Location` | 422 invalid name/code, 409 code taken |
| GET | `/v1/items/?status=active` | `listItems` | 200, paginated (`page`, `pageSize`) | — |
| GET | `/v1/items/{id}` | `getItem` | 200 | 404 |
| PATCH | `/v1/items/{id}` | `updateItem` | 200 | 404, 422, 409 code taken / archived |
| POST | `/v1/items/{id}:archive` | `archiveItem` | 200 | 404, 409 already archived |
| POST | `/v1/items/{id}:restore` | `restoreItem` | 200 | 404, 409 not archived |
| DELETE | `/v1/items/{id}` | `deleteItem` | 204 | 404, 409 still active |

All need a signed-in caller (401) whose role is granted the operationId in `config/access-control.json` (403).

## Follow one request: archive

`POST /v1/items/{id}:archive`

1. `router.py`: `require_access()` checks `archiveItem` is granted; calls `use_cases.archive(id)`.
2. `item_use_cases.py`: loads the item through the repository port (404 if missing).
3. `entities.py`: `item.archive(at=now)`:
   1. rule: `ensure_can_archive(item)` from `policies.py` (409 if already archived),
   2. change: sets the status,
   3. event: records `ItemArchived`.
4. Use case: saves through the port, hands the event to the publisher.
5. `sqlalchemy_item_repository.py`: writes the row (no commit).
6. The request middleware commits; then `LoggingEventPublisher` logs `ItemArchived`.
7. `schemas.py`: `ItemResponse` shapes the JSON reply.

## Make it yours

1. **New field:** value object → entity → table (`models.py`) → repository mapping → schemas.
2. **New rule:** a function in `policies.py` + an error class in `exceptions.py`; call it as the first line
   of the entity method it protects. If it needs other records, the use case fetches the fact and passes it in.
3. **New change:** an entity method: rule → change → event.
4. **New endpoint:** use-case method → route with a new camelCase `operation_id=` and `rate_limit(...)` →
   grant it in `config/access-control.json`.
5. **Table changed:** `uv run alembic revision --autogenerate -m "..."`, review it, `uv run task upgrade`.
6. **Check:** `uv run task check`, `uv run task type-check`, `uv run task test`.

Never check a role in code, never commit in a use case or repository (the request does), never import another
module's internals (use its `public.py`).
